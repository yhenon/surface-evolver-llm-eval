# Task fairness repairs — 30 September 2026

Scope: the seven JSON files currently present in `tasks_audit`. The September 18 audit covered a different set: `cross_slot`, `pyramid_mound`, and `w_groove` are no longer present, while `rect_groove` and `v_groove` are now included. No reference solution or existing area/energy target was changed.

## Changes shared by the tasks

- Static requirements no longer mandate mesh counts, body-row formatting, section aliases, constraint numbers, parameter declaration spelling, algebraic expressions, or evolution steps. The only required substring is the explicitly named `gogo` command for evolving tasks. Command hygiene remains required by every prompt.
- Initial coordinates, connectivity, triangulation, and initialization parameters are explicitly optional. Initialization defaults were removed from dynamic checks and public scripts as well. Physical parameter defaults remain required.
- Sample evolution recipes are optional. The evaluator calls the submission's `gogo` once. Prompts state numerical tolerances and suggest a stability diagnostic, without requiring one discretization or descent sequence. Existing finite-mesh numerical targets are retained; this change does not certify continuum limits or acceptance of every alternative discretization.
- Wetting domains, mobile contact lines, dry regions, surface tension, and energy conventions are explicit. Gravity-bearing tasks require density 1 relative to the ambient phase and state gravity's direction.
- Evolver checks exact body count, prescribed-volume status and target, physical defaults, free-surface tension, and vertex admissibility. Relevant invariants are measured before and after evolution, so `gogo` cannot conceal incorrect defaults. Actual initial volume is deliberately unrestricted.
- Public validation scripts expose the same measurements used by grading.
- Each audit task has a disclosed, configurable 60-second Evolver grading budget. Other tasks retain the existing 10-second default. Timeout output is decoded consistently and produces a failed result instead of a bytes/string exception. The larger budget gives headroom over the local reference runtimes; it is not a hardware-independent calibration.
- After `read`, command hygiene recognizes definition boundaries, rejects arbitrary top-level invocations, and catches commands following a definition on the same line. Quoted strings are preserved during comment handling. This is a lightweight conformance check, not a complete Evolver parser or an execution sandbox.

## Task-specific repairs

| Task | Clarification and validation |
| --- | --- |
| `cube` | Explicitly includes all eight corners, outward orientation, all six free sides, and no wetted substrate. Allows triangulation and subdivisions. Dynamic checks enforce the unit bounding box, boundary planes, closed edges, outward facet orientation, exact body count, and prescribed volume. |
| `bridge_three_plates` | Specifies the central half-space intersection, unbounded plates, three distinct mobile wetted patches, no contact with plate intersections, unit tension, and dry-plate energy zero. Gives centers and tangents only for the optional initialization. Equivalent cosine algebra is accepted. |
| `bridge_two_rods` | Specifies solid exclusion, inward-facing mobile patches, a connected untwisted non-wrapping bridge, dry-rod energy zero, unit tension, and the convex-constraint gap coefficient of 1. Initial loop sizes and mesh-quality command spellings are unrestricted. |
| `fiber_bridge_crossed` | Explains the separated perpendicular axes, surface gap, inward-facing patches, branch-cut avoidance, untwisted connectivity, gap coefficient, and required physical-volume correction for the omitted x-parallel patch. Equivalent closed-volume formulations are allowed. |
| `square_well` | Fixes the bottom datum at z = 0, unbounded wall height, fully wetted bottom, vertically sliding wall contacts, corner membership, density, and free-surface tension. Sets the constant bottom wetting energy to zero and measures wall wetting from the bottom. AA is a side length and suggested starting height, not a rim. |
| `rect_groove` | Specifies the bottom and both wetted side patches, dry remainder, connected perimeter, mobile wall-bottom crossings, no end walls, density, and energy from the entire wetted area. |
| `v_groove` | Specifies the physical wall half-planes, two wetted patches joined at the apex, mobile endpoints, density, and both volume and gravitational-energy contributions of omitted sloping patches. |

The volume, gravitational-energy, and gap-energy conventions follow the [Surface Evolver energy documentation](https://kenbrakke.com/evolver/html/energies.htm) and [geometric-element documentation](https://kenbrakke.com/evolver/html/elements.htm).

## Validation and reference exceptions

```sh

```

The suite includes 13 audit regression tests, with multiple task and mutation subcases, in addition to the existing 17 tests. Evolver integration tests skip explicitly when the executable is unavailable.

Local Surface Evolver 2.70 results:

- All six references whose physical defaults match their current tasks pass the updated grading checks.
- Cube `facets`, whitespace, and parenthesized-volume variants pass. Reordered plate cosine expressions pass.
- Translated cubes, an extra body, an unprescribed volume, incorrect liquid density, and a command that repairs an incorrect physical default during `gogo` fail the relevant checks.
- Timeout byte output is handled without an exception. Arbitrary post-`read` invocations, including `recalc` and commands following a definition, are rejected.
- The saved V-groove reference uses `v_angle = 120` and `contact_angle = 60`; its task specifies 60 and 70. It therefore still fails. Substituting the task angles in memory passes; the saved reference remains unchanged. That reference also omits the sloping-wall gravitational-energy correction now explicitly required by the prompt. Passing scalar tolerances alone does not establish that this reference's physical functional is complete.

The older audit's W-groove volume defect, cross-slot energy-offset discrepancy, and pyramid evolution defect were not repaired: those tasks are absent from the requested directory, and reference changes were excluded by the request. The original report and evidence remain historical records, not descriptions of the updated tasks.

The added geometric checks address the demonstrated cube counterexamples and basic admissibility. They are not a complete verifier of contact-loop connectivity, continuous curved-facet solid exclusion, every omitted-solid integral, or convergence. Those physical requirements are now stated explicitly; exhaustive topology and continuum validation would require additional work and independent reference calibration.
